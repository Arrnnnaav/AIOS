# GitHub read-only Work view

26 October 2026. The owner selected GitHub read-only as Orbyn's first connected app. The Work tab accepts a fine-grained personal access token, validates it with `GET /user`, stores it in Windows Credential Manager, and offers explicit `GET /user/repos` and `GET /repos/{owner}/{repo}/issues` views. The service projects at most 30 repository entries and 20 open issues for the page. It does not send GitHub text to a model, Brief, Brain, routine, or Act path. Disconnect removes Orbyn's local credential; the user can revoke the token on GitHub separately.

GitHub's official REST documentation describes [token authentication](https://docs.github.com/en/rest/authentication/authenticating-to-the-rest-api), [authenticated repository listing](https://docs.github.com/en/rest/repos/repos#list-repositories-for-the-authenticated-user), and [repository issue listing](https://docs.github.com/en/rest/issues/issues#list-repository-issues). The token should be limited to selected repositories, Metadata read and Issues read permissions. No live token or GitHub account was used in this slice; HTTP tests use a fake transport.

Focused `tests/test_workspace_app.py`, `test_workspace_github.py` and `test_workspace_research.py` passed 60 tests. The extracted page script passed `node --check`. A seeded 500 px Playwright flow connected, loaded a repository and issue, and found no page errors; markup-shaped repository/issue text stayed text.
