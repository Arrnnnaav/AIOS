# Aside for Windows: static teardown (29 October 2026)

Target: the Aside browser already installed on the owner's machine, version
1.0.1022.1 (agent extension 1.26.1023.5). Nothing was run; files were copied
to a scratch folder and read as data.

Method: the agent extension's `manifest.json` and bundled `SKILL.md` files
were read as text; printable ASCII and UTF-16 strings were pulled from
`AsideComputerUse.exe` (native C++/WinRT, 4.5 MB) with a stdlib script.

## What it is

- A Chromium fork with a built-in MV3 "Browsing Agent" extension (debugger,
  cookies, history, nativeMessaging, `<all_urls>`, direct
  `api.anthropic.com` host permission) and a side panel.
- `aside-daemon.exe` (133 MB single-file runtime) with `node-pty`, a Rust
  N-API add-on for local memory (SimSIMD vector search, a local ONNX
  multilingual embedding model) and about 35 bundled skills (Office files,
  Google apps, Slack, Notion, password managers, captcha solver,
  computer-use).
- `AsideComputerUse.exe`, a Windows computer-use helper: UI Automation tree
  with change events, Windows OCR fallback, window capture, `SendInput`,
  plain-text paste, a tray "Stop Aside using <app>" control and a low-level
  input hook as a "physical-input stop monitor". The model drives it from a
  JS REPL (`computer.getApp(name)`, `app.click([N])`, `getAXState` diffs).

## Its action guards, from the helper's own refusal strings

| Aside refuses when | Orbyn |
|---|---|
| The point is off screen or covered by another window | **Taken (this commit)**: `act.blocker` with the bound window |
| Windows key / system shortcuts | **Taken (this commit)**: `chord_events` refuses `win` and Alt+Tab |
| Password or protected field | Already: password controls never become candidates (`frame.py`) |
| Elevated app, security or shell UI | Already: `act.blocker` (UIPI, secure desktop) |
| Element changed since the last state | Already: `teach.resolve` re-reads the control; frames older than `MAX_FRAME_AGE_S` re-ask |
| Stop does not match the active run | Already: ESC / Stop / `--seconds` (D020) |
| The user is using the mouse or keyboard | Not taken: needs a low-level hook to tell user input from Orbyn's own; recorded in FOLLOWUPS |
| Keyboard focus moved mid-typing | Not taken: Orbyn sends a step's keys in one `SendInput` batch; recorded in FOLLOWUPS |

## Not taken, and why

- Driving signed-in sites through a debugger extension, cookies and history
  access: authority and egress outside rule 1 and rule 6.
- Hosted skills for Gmail, Slack, Notion and password managers: egress (rule 6, D141).
- Captcha solving: not a use Orbyn supports.
- Local embedding memory: matches the upgrade path already noted for
  `session.relevant`; worth doing only if word-overlap misses in real use.

## Also read: Antigravity (installed, same day)

The Electron `app.asar` (read with a stdlib asar lister) is a thin shell:
updater, tray, IDE install wizard and a host bridge to `language_server.exe`
(152 MB Go). Strings in that binary show the agent's policy layer: terminal
auto-execution levels (`OFF`, `REQUIRE_REVIEW`, `PROCEED_IN_SANDBOX`,
`TURBO`), a URL denylist that defaults to denying when it cannot be checked,
file view/edit allowlists, a "policy guardian" post-tool check ("data
exfiltration: sensitive file sent to non-allowlisted remote endpoint"), and
a browser subagent driven over CDP. Orbyn has no terminal or file-writing
agent and already keeps files on the device (rule 6), so nothing was taken;
the fail-closed defaults match Orbyn's.
