# Live run and test lanes, 16 October 2026

Branch `feature/product-shell-task-graphs`. Session commits b906949, 0455761 and
the scrub tightening that follows them.

## Workspace live run (real models, through the app's HTTP API)

A script drove the app's HTTP API as the page does (`say`, `research`,
`evidence`, `ideate`, `plan{idea}`, `plan_edit`, `handoff_export`, `act`,
`handoff_import`, `plan`). Brain and briefs went to `.tmp/live-ws`. Providers:
NIM `nvidia/nemotron-3-super-120b-a12b` (System Two), `jev-1.13.0` (checks),
Tavily (research). The raw log stays local (`.tmp/live-ws.log`, untracked)
because it holds model text. The provider attribution log is
`%LOCALAPPDATA%\GhostCursor\provider-requests.jsonl`.

What worked on the final run:
- Chat replies took 7–10 s. The Jev chip suggested `plan` after the first message.
- Memory candidates were saved. With the fix, a restated memory is no longer
  stored twice.
- Research gave a cited answer from 4+ sources (13–16 s); `evidence` showed the
  supporting passages.
- Ideate gave 3–4 approaches with assumptions and unknowns (11–16 s).
- A plan from approach 2 was produced; the plan memories were shown.
- Handoff export did not contain the email the user typed (the script asserts
  it). Act was refused from the workspace.
- The receiver got an assistant turn plus plan revision 1, with an empty goal.
  A new message plus `plan` gave revision 2.

Defects found and fixed:
1. `state()` read the Brain (sqlite) on the request thread once a plan existed,
   so every poll failed. Fixed in b906949.
2. A memory restated each turn was stored each turn. Fixed in b906949.
3. Scrub turned link paths (`top-10-quarterly-sales-review-...`) into
   `[token]`. 0455761 fixed this. The D162 review then found that this commit
   let some base64url keys through (BLOCKING), and the change was tightened
   (see below).

Not fixed:
- On one run, a plan from an idea failed. NIM returned `invalid_output`
  (attribution log, 21:03:15) and Ollama was not running (`unavailable`). In a
  rerun, 12 of 12 plans from ideas were valid (NIM only). Their step counts
  reached 19 against a cap of 20, so a 21-step answer is the likely cause.

## Scrub fuzz (seeded, 20,000 random keys per format)

Each key was scrubbed both as plain text and as a URL path
(`fuzz_keys.py`, seed 7, kept in the session scratchpad). Leaks after
tightening: glpat 0, Google `AIza` 0, Anthropic `sk-ant` 0, OpenAI `sk-proj` 0,
GitHub `ghp_` 0, Stripe `sk_live_` 0, Slack `xoxb` 0, 68-char base64url 0, AWS
secret 0, UUID 0. Before the `_MIXED` rule, glpat leaked 681 of 20,000. The
digit-free ones were never masked. Guard mutations: 10 of 10 killed.
