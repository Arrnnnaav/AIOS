# MP0 — Trust Foundation and Act Release

## Purpose and phase grouping

This Mega Phase owns the truth of the current baseline, the exact production authority path, release signing, and the gated activation of PowerPoint Limited Act v1. It groups detailed phases 1–2:

- **Phase 1 — Repository/evidence baseline and PowerPoint Act signing, acceptance campaigns, and activation**
- **Phase 2 — Shared trust, privacy, identity, and evidence contracts**

Before activation, only standalone Spatial work, read-only evaluation, and documentation/design work within the current `ROADMAP.md` scope may proceed. Do not wire manager Ideate/Plan, Spatial Context into the manager brief, semantic application workflows, or Act authority before the final activation review returns READY. The MVP must not enable execution until Phase 1 closes.

## Phase 1: baseline, Act release closure, and plan governance

1. Reconfirm branch, tree, commit, installed bundle, signed manifest, release keys, current `ROADMAP.md`, open follow-ups, and the exact diagnostic/acceptance classification of every retained run.
2. Map current repositories and source docs: Orbyn/AIOS, standalone Spatial, original unified plan, Jev/System-One addendum, and current evidence. Record conflicting sequencing rather than silently choosing old prose.
3. Adopt this plan folder as the forward planning authority after independent review. Keep `CLAUDE.md`, `FLOW.md`, `ROADMAP.md`, and `DECISIONS.md` as current operational authorities until focused reconciliations are reviewed and committed.
4. Put a regression/replay fixture beside each newly specified contract at the time it is introduced. Build shared evaluation infrastructure later; do not defer quality tests until then.

Re-read the current Phase 0/Act rows in `ROADMAP.md` before planning each task. Release details that must be revalidated include signing-key custody/rotation state, current exact bundle bytes, counted campaigns, animation/desktop lanes, and final D032 activation review. Their live status can change; do not treat this document’s baseline as fresher than repository state.

Order:

1. Reconcile the live ROADMAP gate list, release-key custody, exact source bytes, bundle manifest, policy values, and required campaign/lane matrix. Do not use this plan's known risks as proof they remain current.
2. Establish custody of an approved non-ephemeral signing identity or complete the D144-governed rotation: public-key identity, key manifest, revocation semantics, re-sign provenance, protected private-key handling, and bundle compatibility.
3. Build the exact release candidate from tracked canonical sources and prepare the tests/evidence package. Do not count a campaign yet.
4. Obtain the required independent pre-campaign D032 READY verdict on the exact release candidate, authority path, and tests. A NOT READY verdict returns to remediation; no counted run occurs before READY.
5. Sign/install the reviewed payload without changing its reviewed bytes, then run the fresh counted UIA/object-model campaigns and remaining live lanes on those exact bytes. Separate diagnostics, validation attempts, excluded attempts, and counted runs; retain every attempt and apply only the predeclared lane-level discard policy.
6. Obtain the separate final D032 activation review over the reviewed source/bundle plus the newly retained campaign and lane evidence. Activate only if it returns READY and every current closure item passes. Record the exact enabled/disabled runtime state; disabled execution requests must fail closed.

The approved UI must derive its enabled state from the trusted release/catalog status. An `ACT_STATUS` display flag alone is insufficient: canonical execution entrypoints must independently reject unavailable or unactivated authority.

## Phase 2: cross-cutting trust foundation

Before web/PDF/document text is passed to any model, establish the **Untrusted Observation Boundary** in the first Spatial/research slice. All external page/document/UIA/OCR/search text is tainted content; trusted user goals, policy, provider rules, and signed capability metadata are separate fields. Retrieval content cannot issue instructions to the model or runtime.

Establish shared versioned contracts for SpatialContextReference, EvidenceGraph, ResearchTrace, ObservationFrame, ActionEvidence, and PersonalMemory. Contracts must be data-only and must not grant authority. Keep target identity/freshness, execution permission, and verification in deterministic runtime/plugin owners.

Define privacy categories and outbound policy alongside cloud provider integration: minimum context, no credentials or raw process/window identifiers, no screenshot/image transfer unless permitted, no provider response stored as memory by default, and visible provider/data-use status. **D147 (D141-R2) adopts cloud-by-default reasoning for the trial period** (owner-approved 24 September 2026; independent D032 review outstanding), so this policy work is now a prerequisite of shipping the gateway rather than a precondition of a future amendment. Local execution remains a supported, tested configuration. Side-effecting connectors keep their separate gates under D144.

## Interfaces and invariants

- `ActReleaseState`: trusted source derived from signed catalog/activation data; closed state rejects the execution API.
- `SpatialContextReference`, `EvidenceGraph`, `ResearchTrace`, `ObservationFrame`, `ActionEvidence`, `PersonalMemory`: versioned context/provenance values, never policy objects.
- Preserve signed plugin compatibility, `authorize_intent()`, fresh binding, per-node authorization, one approved graph, and independent verification.
- Provider/network failure cannot enable a fallback execution path.

## Verification and exit criteria

- Signature and manifest reproduction from clean tracked sources; verify installed payload bytes equal reviewed bytes.
- Positive and negative activation tests, including attempted direct runtime calls while disabled.
- D018 mutations for skipped signature checks, stale manifests, disabled-state bypass, untrusted text promoted to instructions, and context references treated as selectors/authority.
- D025 lane separation; D034 durable evidence for every measured gate; D032 external re-derivation and READY result.
- Phase 1 closes only when `ROADMAP.md` and current decision/evidence records state activation with exact bundle identity. Otherwise the MVP may ship non-executing features only.
