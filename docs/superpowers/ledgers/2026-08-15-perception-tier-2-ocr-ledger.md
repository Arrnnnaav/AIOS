### Rulings

Ruling P1: Task 6's `test_an_exact_ocr_read_grounds_at_rung_4` is wrong as written and must be changed. It feeds an OCR element whose name EXACTLY equals the claimed name, but rung 2 (`e.name == claimed.name`) runs first and matches it, so the test would return rung 2 and fail its own assertion. The spec deliberately leaves rung 2 open to OCR because exact equality is a strictly higher bar than a 95 fuzzy score, so the code is right and the test is wrong. Replace the fixture with a case-only difference: claimed `"Select area"`, OCR read `"Select Area"`. Rung 2 is case-SENSITIVE (`==`) so it misses; rung 3 excludes OCR; rung 4 casefolds and scores 100.0, clearing the floor. Verified with rapidfuzz. Cost if wrong: a test that exercises rung 2 instead of rung 4, leaving rung 4 unproven — which is why it is being fixed before dispatch rather than after.

Ruling P2: Task 8 may modify `tests/test_overlay.py` to ADD a 16th check, notwithstanding the Global Constraint that existing tests pass unchanged. The constraint's purpose is to forbid EDITING existing assertions to accommodate new behaviour — that is the signal the collaborator contract broke. Adding a new check to a harness whose whole job is to grow with the overlay's visual states is the opposite: it is how FRESH and DIMMED were each verified, and the previous milestone added the 15th check to this same file by the same reasoning. No existing check may be altered. Cost if wrong: the task reviewer flags a legitimate addition, which the ledger entry pre-answers.

Ruling P3: Task 4's `test_at_most_three_reads_merge_into_one_candidate` asserts `len(read.text.split()) <= 3`, which counts WORDS while `MERGE_MAX_PARTS` caps PARTS. The two coincide only because the fixture uses single-word reads. Accepted as written rather than rewritten: the fixture is single-word by construction, so the assertion is sound for what it tests, and a parts-counting assertion would require the merged read to carry provenance it has no other reason to hold. Cost if wrong: a merge of three multi-word reads would produce more than three words and this test would not notice — the cap itself is still enforced in code and covered by the geometry tests.

Ruling P4: Task 1 is a human hand-off gate and cannot be dispatched. No implementation task may begin until it reports PASS. Recording this as a ruling rather than a note because it inverts the skill's default of continuous execution: the controller deliberately stops here, and that stop is correct rather than a stall. Cost if wrong: none — a FAIL means tier 2 was never viable and every task after it would have been wasted work.
